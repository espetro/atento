priority model (revised per review — READ-FIRST)
  The workflow is driven by an agent or deterministic tool; the UI is
  primarily a READ surface plus a small set of deliberate write actions.

  CORE (daily surface, read-mostly):
    triage        - the daily loop: pick a collection, scan the list,
                    preview a link, act (archive / schedule / discard /
                    re-extract / open)
    needs-login   - "only you can fix this": parked links grouped by
                    remediation; makes the login process (which blocks
                    ingestion) trackable
    collections   - navigation spine (chrome of the core views)

  SECONDARY (chrome/dialogs, not standalone destinations):
    ingest        - dialog over any view (?dialog=ingest); a write action
    run status    - shell-level status chip + detail drawer; a write
                    action ("run a pass") with a read surface
    settings      - READ-ONLY config display + pairing; no editable
                    settings UI anywhere

user flows
  triage       - pick a collection, scan the list, act on the selected
                 link, read it in the preview pane
  attention    - folded into needs-login: needs_login + blocked +
                 errored + review collections, each with remediation
  ingest       - add links (file / pasted text / URL list) via dialog;
                 returns a job summary, never link payloads
  ops          - run a pass / watch it (shell chip + drawer), check
                 config + health (read-only settings), pair the
                 extension

data stack (DECIDED — M4 gate)
  - @tanstack/svelte-query v6 for ALL server-side state (already a
    devDependency; src/lib/api.ts createQueryClient is the pattern).
    SSE events invalidate/patch queries; no hand-rolled fetch state.
  - @tanstack/svelte-virtual for the link list (already a
    devDependency) — DOM stays bounded at 1k+ links.
  - formisch + valibot for form validation — the ingest dialog inputs
    (urls/text/file) and any remaining forms. NOT yet installed; add as
    devDependencies+dependencies of @linkinbox/ui in M4b.
  - Server payloads stay zod-typed at the API boundary
    (packages/server/src/schemas.ts); the UI validates FORM input with
    valibot schemas, it does not re-validate API responses.

styling (partially decided — see SPEC-SUMMARY open questions)
  Svelte 5 + Tailwind v4. Semantic classes only, defined in the ui
  stylesheet: `.btn`, `.chip`, `.chip-state-*`, `.pane`, `.list-row`,
  `.kbd`. State colors via `.chip-state-*` tokens only.
  REALITY CHECK: packages/ui currently ships daisyUI 5 as the theme
  layer (@plugin 'daisyui' in src/app.css) and Bits UI is NOT installed.
  The earlier "Bits UI 2.20, no daisyUI" decision predates the package;
  confirm direction before M4b (open question Q1). Type mix: bold
  display + light body (user's stated taste; see references/tokens.md).

API surface the specs consume (all exist unless marked [gap])
  GET  /api/collections/summary           counts per collection + needsLoginHosts
  GET  /api/collections/{name}            paginated read (json; tsv/jsonl/md export)
  GET  /api/links?q&status&state&category&host&stale&limit&offset
  GET  /api/links/{id}                    detail projection (markdown, enrichment)
  PATCH /api/links/{id}                   title / note / tags only
  POST /api/links/triage                  { ids[], action } -> { updated }
                                          (action=schedule carries NO date —
                                          see scheduling note below)
  POST /api/links/{id}/reextract          { adapter?, limit? } -> outcome | 409
  GET  /api/links/{id}/artifacts/{name}   screenshot/snapshot bytes
  POST /api/ingest                        file | text/plain | json kind -> job summary
  GET  /api/ingest/{jobId}                job progress { total, done, cursor, ... }
  POST /api/run                           one full pipeline pass -> RunResult
  GET  /api/runs/{id}                     run journal row
  GET  /api/pipeline                      byState / byParkReason / byHost overview
  GET  /api/events                        SSE; evt:{"l","r","i"} composite cursors,
                                         Last-Event-ID / ?since= resume
  GET  /api/metrics?last=                 per-stage + daily token/cost buckets
  GET  /api/pair/code                     [M5, unmerged] -> { code, expiresAt }
                                         (5-min single-use code; bearer-gated
                                         on non-loopback binds, open on loopback)
  POST /api/pair                          [M5, unmerged] { code } ->
                                         { captureToken, serverToken } —
                                         redeemed by the EXTENSION, never by
                                         the UI; the UI only displays the code
  [gap] GET  /api/browsers                adapter kinds/caps/health (CLI-only today:
                                         `linkinbox browsers`) — M4b
  [gap] config-read                        current config values for the
                                         read-only settings view — M4b
  [gap] state_data.frameable writer        extractor records frameability —
                                         extractor milestone (post-M4)
  [gap] artifact/snapshot writer           snapshot.png capture — extractor
                                         milestone (post-M4)
  [gap] pairing-status read                "paired? last capture?" — needs a
                                         server read; M4b or later

scheduling (DECIDED — out of scope for this UI)
  Recurrence is a HARNESS feature (apps/harness harness.toml:
  `schedule = "<cron>"`, `on_ingest = true`) — NOT an API/MCP/service
  concern. There is NO scheduledFor API change, NO date picker writing
  to the API, NO scheduling endpoints in these specs.
  The triage `s` key fires the existing schedule action:
  POST /api/links/triage { action: 'schedule' } with no date — the FSM
  accepts optional scheduledFor (packages/core/src/fsm/events.ts) but
  the wire schema (packages/server/src/schemas.ts TriageBody) does not
  carry it, so scheduledFor lands as null. A date/requeue picker is
  harness-UI future work, explicitly out of scope for M4.

keyboard contract (all core views, when no input/dialog is focused)
  j / k        move selection in the link list
  /            focus search
  a / s / d    archive / schedule / discard the selected link(s)
               (s = schedule with no date — see scheduling note)
  r            re-extract the selected link (opens adapter picker when >1 adapter)
  o            open the selected link's URL in the system browser
  1 - 4        switch preview tabs: Reader / Metadata / Snapshot / Live
  ?            show the keymap overlay
