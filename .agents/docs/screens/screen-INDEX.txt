user flows
  triage       - the daily loop: pick a collection, scan the list, act on the
                 selected link (archive / schedule / discard / re-extract),
                 read it in the preview pane
  attention    - surfaces that need the human: needs_login + blocked + errored
                 collections, run results that ended "needs you"
  ingest       - add links (file / pasted text / URL list) via dialog; returns
                 a job summary, never link payloads
  ops          - run status, metrics-adjacent run journal, settings
                 (browsers, sources, schedule, extension pairing)

styling (decided — M4b implementation; supersedes the M4-gate "Bits UI +
  Tailwind v4, no daisyUI" text)
  Svelte 5 + daisyUI 5 kept as the base layer + hand-rolled semantic classes
  in app.css. Bits UI and Tailwind v4 were dropped during implementation;
  forms use @formisch/svelte + valibot. Semantic classes only for surfaces:
  `.btn`, `.chip`, `.chip-state-*`, `.pane`, `.list-row`, `.kbd`, `.rail-row`,
  `.field`, dialog classes — defined over CSS custom-property tokens
  (`--color-surface/ink/accent` + state colors). No raw palette utilities
  for surfaces. Type mix: bold display + light body (see
  references/tokens.md).

API surface the specs consume (all exist unless marked [gap])
  GET  /api/collections/summary           counts per collection + needsLoginHosts
  GET  /api/collections/{name}            paginated read (json; tsv/jsonl/md export)
  GET  /api/links?q&status&state&category&host&stale&limit&offset
  GET  /api/links/{id}                    detail projection (markdown, enrichment)
  PATCH /api/links/{id}                   title / note / tags only
  POST /api/links/triage                  { ids[], action } -> { updated }
  POST /api/links/{id}/reextract          { adapter?, limit? } -> outcome | 409
  GET  /api/links/{id}/artifacts/{name}   screenshot/snapshot bytes
  POST /api/ingest                        file | text/plain | json kind -> job summary
  GET  /api/ingest/{jobId}                job progress { total, done, cursor, ... }
  POST /api/run                           one full pipeline pass -> RunResult
  GET  /api/runs/{id}                     run journal row
  GET  /api/pipeline                      byState / byParkReason / byHost overview
  GET  /api/events                        SSE; evt:{"l","r","i"} composite cursors,
                                         Last-Event-ID / ?since= resume
  GET  /api/metrics?last=                 per-stage + daily token/cost buckets
  GET  /api/browsers                     adapter kinds/caps/health (added M4b)
  GET  /api/pair/code                     mint one-time pairing code (added M4b)
  POST /api/pair                          redeem pairing code (added M4b)

keyboard contract (all views, when no input/dialog is focused)
  j / k        move selection in the link list
  /            focus search
  a / s / d    archive / schedule / discard the selected link(s)
  r            re-extract the selected link (opens adapter picker when >1 adapter)
  o            open the selected link's URL in the system browser
  1 - 4        switch preview tabs: Reader / Metadata / Snapshot / Live
  ?            show the keymap overlay

implementation notes (M4b)
  - state_data.frameable shipped: extractor records it; Live tab iframes
    only when true, else snapshot + "Open in browser" (no proxy).
  - Snapshot artifact convention: snapshot.png via
    /api/links/{id}/artifacts/snapshot.png; honest empty state when absent.
  - Saved filters: localStorage v1 keyed by collection (no server persistence).
  - `schedule` triage action still takes no date (TriageBody = { ids, action });
    the spec'd date picker was NOT built — needs a scheduledFor API field.
  - Settings is read-only except pairing-code mint/copy; schedule section
    explains cron/launchd ownership and shows "next run unknown".

known gaps (to resolve during M4 implementation, not in this docs pass)
  - state_data.frameable does not exist yet; Live tab falls back to
    snapshot + "Open in browser" until the extractor records it.
  - No artifact writer ships yet; Snapshot tab renders only when
    /api/links/{id}/artifacts/<name> returns bytes (convention: snapshot.png).
  - Saved filters have no server persistence story yet; v1 keeps them in
    localStorage keyed by collection.
  - `schedule` triage action takes no date in the current API
    (TriageBody = { ids, action }); the date picker needs either a
    scheduledFor field or a follow-up PATCH — open question for the user.
