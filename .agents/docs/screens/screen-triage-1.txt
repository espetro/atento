The daily-driver surface. Three columns on desktop — collections rail,
link list, preview pane — collapsing to list -> detail on narrow
viewports. Every row and pane is live: state transitions arrive over
GET /api/events (SSE) and update rows in place; nothing requires a
manual refresh.

Collections are pipeline positions, not folders: enriched, pending,
needs_login, blocked, errored, review, triaged (see
packages/core/src/collections.ts). The list shows the selected
collection; the preview pane shows the selected link with four tabs.

| Collections rail | required | Left column; collection rows with counts (GET /api/collections/summary), HOSTS group (needsLoginHosts + busiest hosts from GET /api/pipeline byHost), SAVED group (user filters, localStorage) |

| Load more | action | "load more · N remaining" appends next page (limit += 50, offset paging; collections cap 200) |

| Tab bar | required | 4 tabs, `1`-`4` shortcuts; badge on Snapshot when no artifact (dimmed), on Live when not frameable (dimmed + "snapshot" fallback note) |

| Metadata tab | required | Enrichment card: category, priority, why_it_matters, read_minutes, expires_at + expiry_reason, confidence bar; editable fields title/note/tags with save-on-blur PATCH; "Re-extract with adapter…" button opens adapter picker (lists configured browser adapters; disabled with reason when none) |

## Behavior

- URL state is the single source of truth: `collection`, `q`, `state`,
  `category`, `host`, `stale`, `selected`, `tab` all live in
  URLSearchParams (existing convention in packages/ui/src/lib/urlState.ts).
  Back/forward and shared links restore the exact view.
- List data: GET /api/links with the active filters, `limit`/`offset`
  paging (default 50, matching the server default; collections reads cap
  at 200). Rows are the pipeline projection: `state`, `reason`,
  `next_attempt_at`, `host`, `updated_at` ride along additively.
- Live updates: one EventSource on /api/events per session. `link`
  events patch the affected row in place (state chip, collection
  membership — a row that leaves the collection animates out); `run`
  and `ingest` events feed the run-status and ingest-job surfaces.
  Reconnect uses Last-Event-ID automatically; the composite
  `evt:{l,r,i}` cursor means no family is skipped.
- Triage actions POST /api/links/triage `{ids:[selected], action}`;
  multi-select (shift-click range, cmd-click toggle) batches ids into one
  call. Optimistic update with rollback on error. `discard`/`archive`
  offer a 6s undo toast that re-triages back to inbox/scheduled.
- `r` on a link with >1 configured adapter opens the adapter picker
  (Bits UI dialog listing `linkinbox browsers` ids + health); on a
  single-adapter setup it fires POST /api/links/{id}/reextract directly.
  409 responses (illegal state / busy) surface the server's reason
  inline, e.g. "extract is busy — run 41 holds the lock".
- Metadata edits PATCH only title/note/tags — enrichment fields are
  model output and are never hand-edited (re-extract instead). The form
  makes this legible: enrichment fields render as read-only chips with a
  "generated" caption; only the three user fields are inputs.
- Snapshot/Live degrade honestly: missing artifact → dimmed tab + empty
  state; `frameable` absent/false → Live tab shows the snapshot and an
  "Open in browser" button. There is no proxy that strips headers —
  that was an explicit product decision (login walls and paywalls must
  not be silently bypassed by the UI).
- Keyboard: single-key shortcuts are inert while an input, textarea,
  select or open dialog has focus; `/` always focuses search from
  anywhere else. `j`/`k` wrap at list ends (or stop — open question,
  default wrap). All motion respects prefers-reduced-motion.
- Responsive: ≥1100px three columns; 760–1099px rail collapses to an
  icon strip; <760px single-column list with push-detail preview.
  UILOOP gates apply: 0 console errors/warnings, 0 axe
  critical/serious, verified at 375×812, 768×1024, 1440×900.
